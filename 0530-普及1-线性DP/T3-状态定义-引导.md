# T3 最长上升子序列 — 状态定义引导稿

> 用途：从"自然但错误"的状态出发，让学生亲手撞墙，再引出"以 `i` 结尾"为什么是必要的。
> 这一步比写代码本身更重要——它是学生第一次体会"状态要为转移服务"。

## 例子

```
a = [1, 5, 2, 4, 3]
答案：3   (1 2 3 或 1 2 4 或 1 2 4... 选 1, 2, 3 / 1, 2, 4 等)
```

---

## 第一回合：学生最自然的写法

> 提问："`dfs(i)` 应该表示什么？"
> 学生大概率回答："前 `i` 个数的 LIS 长度"。

按这个状态写下去：

```cpp
// dfs(i) = 前 i 个数的 LIS 长度
int dfs(int i)
{
    if(i == 0) return 0;
    // ??? 转移怎么写？
    // 选 a[i]：要接到前面某个 < a[i] 的数后面，可前面是什么？我不知道
    // 不选 a[i]：dfs(i-1)
    return max(dfs(i-1), /* 选 a[i] 的情况 */ ???);
}
```

**让学生卡住 1–2 分钟**，然后引导：

> "选 `a[i]` 的时候，它要接在前面 LIS 的末尾。但 `dfs(i-1)` 只告诉你 *长度*，没告诉你 *末尾是什么*——所以你不知道 `a[i]` 能不能接上去。"

**核心结论**：`dfs(i)` 表示"前 `i` 个的 LIS"时，信息量不够，转移无法表达。

---

## 第二回合：补足信息

继续问："那要让转移能写出来，状态里至少要记住什么？"

引导到两条路：

### 路 A：状态里多记一维"末尾值"

```cpp
// dfs(i, last) = 在前 i 个数里，必须接在值 last 之后的 LIS 长度
```

可行，但 `last` 值域大、状态爆炸——pass。

### 路 B：强制规定末尾就是 `a[i]`

```cpp
// dfs(i) = 必须以 a[i] 结尾的 LIS 长度
```

转移自然就出来了：

```cpp
int dfs(int i)
{
    int res = 1;                          // 单独取 a[i] 自己
    for(int j = 1; j < i; ++j)
        if(a[j] < a[i])
            res = max(res, dfs(j) + 1);   // 接在以 a[j] 结尾的 LIS 后面
    return res;
}
```

**为什么这样能转移？**
因为状态里写死了"末尾是 `a[i]`"，所以子问题 `dfs(j)` 的末尾就是 `a[j]`——这是个已知的具体值，可以直接和 `a[i]` 比较。

---

## 第三回合：但答案不是 `dfs(n)`

提醒：`dfs(n)` 是"必须以 `a[n]` 结尾"的 LIS，不是全局答案。

```cpp
int ans = 0;
for(int i = 1; i <= n; ++i) ans = max(ans, dfs(i));
```

> "我们用'以 i 结尾'换来了能写转移的代价，就是答案要遍历所有可能的结尾。"

---

## 第四回合：加 memo，过渡到 DP

加 `memo[i]` 后，递归就是记忆化搜索；把递归换成 `for i` 正向枚举，就是经典 DP：

```cpp
for(int i = 1; i <= n; ++i)
{
    dp[i] = 1;
    for(int j = 1; j < i; ++j)
        if(a[j] < a[i]) dp[i] = max(dp[i], dp[j] + 1);
}
```

**两段代码一字不差地对应**——`dfs(j)` 就是 `dp[j]`，转移结构完全一样。
这一刻，学生第一次看到"DP 的状态定义"不是天上掉下来的，而是被"转移要能写出来"这件事*逼*出来的。

---

## 教学收尾的一句话

> "DP 的状态不是猜的。先尝试一个最自然的状态，写转移；如果写不出来，说明状态记的信息不够——这时候才去想：要补什么？怎么补代价最小？"

这个心法在 T4 LCS、后面的区间 DP、树形 DP 都会反复用到。
