# T2 学生代码修改意见

## 问题定位

代码整体思路是对的（枚举分组 → 计算代价 → 取最优），但搜索空间的设计导致复杂度爆炸，无法通过大数据。

---

## 问题 1：DFS 枚举方式错误，复杂度 O(k^n)

**当前写法：**

```cpp
void dfs(int u) {
    if (u == n) { check(); return; }
    for (int x = 1; x <= k; x++) {
        now[u] = x;   // 把第 u 个礼物分到第 x 组
        dfs(u + 1);
    }
}
```

每个礼物有 k 种选择，n 个礼物共 **k^n** 种枚举，n=30、k=2 时就已超过 10 亿次。

**关键观察：** 最优解中每个发货日一定等于某个礼物的 d[i]。若某发货日不等于任何 d[i]，把它提前到最近的 d[i]，惩罚只会减小，所以只需从 d[i] 的不同取值中选 k 个作为发货日。

**修改方向：**

```
1. 对 d[i] 去重，得到 cnt 个不同日期存入数组 aa[]
2. DFS 改为从 aa[] 中选 k 个（有序组合），枚举次数降为 C(cnt, k)
3. 对于每种选法，将礼物按日期排序后贪心匹配（双指针），O(n) 计算代价
```

---

## 问题 2：check() 每次在栈上零初始化大数组

**当前写法：**

```cpp
void check() {
    int day[5010] = {0};   // 每次叶节点都执行，共 k^n 次
    ...
}
```

`day[5010]={0}` 是 5010 次赋值，乘上 k^n 次调用，开销极大。

**修改方向：** 把 `day` 提到全局，或改为按需置零（只清用到的下标）。更根本的做法是换掉整个 check 逻辑，改用双指针代替桶计数。

---

## 问题 3：没有对日期去重，搜索空间未压缩

若 n=100 个礼物只有 10 个不同日期，当前代码仍枚举 k^100 种分法。去重后只需 C(10, k) 种。

---

## 修改后的整体框架（供参考）

```
读入 → 排序 + 去重 → DFS 选 k 个发货日（有序） → 双指针计算惩罚 → 更新最优
```

对应参考代码的核心逻辑：

```cpp
void dfs(int x, int last) {       // x: 已选第几个发货日，last: 上一个选的下标
    if (x > k) {
        long long val = getPunish();
        if (val < ans) { ans = val; update(); }
        return;
    }
    for (int i = last + 1; i <= cnt; i++) {
        d[x] = aa[i];
        dfs(x + 1, i);
    }
}
```

---

## 总结

| 问题 | 影响 | 修改优先级 |
|------|------|-----------|
| DFS 枚举 k^n 种分法 | 致命，直接 TLE | ★★★ 最高 |
| check() 重复零初始化大数组 | 常数级加速，治标 | ★★ 中 |
| 未去重压缩搜索空间 | 与问题1配套解决 | ★★★ 最高 |

**核心修改：把"给每个礼物选一组"改为"从不同日期中选 k 个发货日"，复杂度从 O(k^n) 降为 O(C(cnt,k)·n)。**
